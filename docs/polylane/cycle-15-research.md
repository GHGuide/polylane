# Cycle 15 research — where app assumptions leak

The repository audit found app-only assumptions in all three discovery layers:
skill triggering says “software product,” the interview asks for a web/mobile/CLI
platform, and documentation assumes a built app with build/install commands. The
planner and runtime are already file- and evidence-oriented, so the git/worktree
engine does not need replacement. The correct generalization is a project profile
adapter before goal decomposition, not separate runners per industry.

Trading is the adversarial profile because a plausible strategy is not evidence of
profit and because a live order is a consequential external action. Its default
completion boundary is reproducible research plus backtest/walk-forward/paper-trade
evidence, including leakage checks, costs, slippage, drawdown, and risk limits. Live
capital remains approval-required. This same pattern generalizes to production
deployments, publication, legal approval, third-party communication, and physical
operations: prepare and verify autonomously; cross the real-world boundary only with
explicit authority.

Progressive disclosure is required because both skill entrypoints are already near
the 500-line skill limit. Keep the domain router concise in `SKILL.md` and put profile
details in one directly linked `references/project-types.md` file.
