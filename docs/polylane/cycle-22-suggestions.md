# Cycle 22 per-lane skill suggestions

The scout considered installed skills against each lane's concrete activity and prior
outcomes.  No GitHub search or installation is justified for a frozen terminal-boundary
certification; uninstalled tools cannot improve the required process evidence.

## `terminal-boundary-audit`

- **Selected — `superpowers:systematic-debugging`:** reconstruct the failure across
  runner environment, nested canary, report, and state before accepting the causal claim.
- **Selected — `superpowers:verification-before-completion`:** require fresh focused
  output, exact nonce/path evidence, an evidence-only commit, and a clean tree before DONE.
- **Not selected — `superpowers:test-driven-development`:** the repair already has a
  red-first regression; this lane must audit it rather than create another implementation.
- **Not selected — `engineering:testing-strategy`:** useful for designing a new test
  architecture, but this cycle grades a frozen acceptance boundary.

## `integrator`

- **Selected — `engineering:code-review`:** independently review the environment boundary,
  exact-tip provenance, and fail-closed behavior.
- **Selected — `ponytail:ponytail-review`:** detect duplicated certification paths or
  unnecessary flags without weakening the one-gate contract.
- **Selected — `superpowers:verification-before-completion`:** issue READY only from fresh,
  reproducible focused/static evidence and leave terminal proof to the coordinator.

Autonomous selection takes these installed defaults.  Every selected skill is delivered
by exact trusted path and fingerprint, read once, and graded from observable evidence.
